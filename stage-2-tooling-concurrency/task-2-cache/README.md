# Потокобезопасный кэш с временем жизни (TTL)

## Общее описание

Реализация потокобезопасного кэша в памяти на языке Go, поддерживающего индивидуальное время жизни (TTL) для каждой записи. Кэш использует `sync.RWMutex` для синхронизации доступа, `time.Ticker` для периодической фоновой очистки истекших записей и `context.Context` для корректного завершения работы очистителя (graceful shutdown).

---

## Функциональные требования

Кэш должен предоставлять следующий набор операций:

- **Set(key, value, ttl)** – добавить или обновить запись с указанным временем жизни. Если `ttl` меньше или равно нулю, запись считается «вечной» (не истекает).
- **Get(key)** – получить значение по ключу. Если запись отсутствует или истекла, возвращается ошибка (или `false`). При обнаружении истекшей записи она немедленно удаляется (ленивое удаление).
- **Delete(key)** – удалить запись по ключу, если она существует.
- **Clear()** – полностью очистить кэш (удалить все записи).
- Фоновая очистка истекших записей происходит периодически с заданным интервалом (например, каждые 5 секунд) с использованием `time.Ticker`.
- Очиститель должен корректно завершать работу при отмене контекста (`context.Context`) без утечек горутин.

---

## Технические требования

- Язык реализации: **Go** (стандартная библиотека, без внешних зависимостей).
- Использование:
  - `sync.RWMutex` для защиты общих структур данных.
  - `time.Ticker` для фоновой очистки.
  - `context.Context` для управления жизненным циклом очистителя.
- Код должен быть документирован и покрыт тестами (включая тесты с `-race`).

---

## Ограничения

- Все данные хранятся исключительно в оперативной памяти.
- Кэш не ограничен по объёму (нет политики вытеснения).
- TTL задаётся для каждой записи индивидуально при вызове `Set`.
- Очистка истекших записей выполняется только по таймеру и при `Get` (ленивое удаление).
- Не допускается использование сторонних библиотек для кэширования (например, `go-cache`).
- Время жизни задаётся в виде `time.Duration`.

## Сценарии тестирования

Для проверки корректности реализации необходимо написать тесты, покрывающие следующие случаи:

1. **Базовые операции**:
   - Успешное добавление и получение записи.
   - Получение несуществующего ключа возвращает ошибку.
   - Обновление существующей записи с новым TTL.
   - Удаление записи и повторное получение.
   - Очистка всего кэша.

2. **Истечение TTL**:
   - Запись с TTL = 1 секунда; через 2 секунды `Get` возвращает ошибку.
   - Запись с TTL <= 0 никогда не истекает.

3. **Ленивое удаление**:
   - При вызове `Get` для истекшей записи она удаляется из кэша и возвращается ошибка.
   - Повторный `Get` после ленивого удаления также возвращает ошибку.

4. **Фоновая очистка**:
   - Установить несколько записей с разными TTL, дождаться очистки, проверить, что истекшие записи удалены, а валидные остались.
   - Убедиться, что очистка не удаляет записи с отрицательным TTL.

5. **Конкурентный доступ**:
   - Одновременные `Set` и `Get` из разных горутин – отсутствие гонок данных (запуск с `-race`).
   - Одновременное обновление одного ключа из нескольких горутин – конечное значение корректно.

6. **Graceful shutdown**:
   - Запустить очиститель, отменить контекст, убедиться, что горутина очистителя завершилась.
   - Убедиться, что после отмены контекста кэш продолжает работать (фоновый поток остановлен, но основные методы доступны).

7. **Интеграционные сценарии**:
   - Комбинация операций с разными TTL и параллельным доступом.
   - Длительная работа (например, 10 секунд) с периодической проверкой состояния.

## Рекомендации по реализации

### Структура данных

```go
type item struct {
    value      interface{}
    expiration int64 // Unix-метка времени (наносекунды), когда запись истекает
}

type Cache struct {
    items  map[string]item
    mu     sync.RWMutex
    ticker *time.Ticker
    done   chan struct{} // или использовать context.Context
    ctx    context.Context
    cancel context.CancelFunc
}
```

### API

```go
func New(cleanupInterval time.Duration) *Cache {
    ctx, cancel := context.WithCancel(context.Background())
    c := &Cache{
        items:  make(map[string]item),
        ticker: time.NewTicker(cleanupInterval),
        ctx:    ctx,
        cancel: cancel,
    }
    go c.cleanupLoop()
    return c
}

func (c *Cache) Set(key string, value interface{}, ttl time.Duration) {
    c.mu.Lock()
    defer c.mu.Unlock()
    var exp int64
    if ttl > 0 {
        exp = time.Now().Add(ttl).UnixNano()
    } else {
        exp = 0 // никогда не истекает
    }
    c.items[key] = item{value: value, expiration: exp}
}

func (c *Cache) Get(key string) (interface{}, bool) {
    c.mu.RLock()
    it, ok := c.items[key]
    c.mu.RUnlock()
    if !ok {
        return nil, false
    }
    // Проверка истечения
    if it.expiration > 0 && time.Now().UnixNano() > it.expiration {
        // Ленивое удаление
        c.mu.Lock()
        delete(c.items, key)
        c.mu.Unlock()
        return nil, false
    }
    return it.value, true
}

func (c *Cache) Delete(key string) {
    c.mu.Lock()
    defer c.mu.Unlock()
    delete(c.items, key)
}

func (c *Cache) Clear() {
    c.mu.Lock()
    defer c.mu.Unlock()
    c.items = make(map[string]item)
}

func (c *Cache) Stop() {
    c.cancel()
    c.ticker.Stop()
    // Дожидаемся завершения горутины (можно через WaitGroup или канал)
}
```

### Очиститель

```go
func (c *Cache) cleanupLoop() {
    for {
        select {
        case <-c.ctx.Done():
            return
        case <-c.ticker.C:
            c.deleteExpired()
        }
    }
}

func (c *Cache) deleteExpired() {
    now := time.Now().UnixNano()
    c.mu.Lock()
    defer c.mu.Unlock()
    for k, v := range c.items {
        if v.expiration > 0 && now > v.expiration {
            delete(c.items, k)
        }
    }
}
```

### Рекомендации по обработке ошибок

- Методы `Get` возвращают `(interface{}, bool)`, где `bool` указывает на наличие валидной записи.
- Для `Set` можно вернуть ошибку, если значение `nil` или ключ пуст (опционально).
- При остановке кэша следует дождаться завершения очистителя с помощью `sync.WaitGroup`, чтобы избежать гонок при закрытии.

### Тестирование

- Используйте `testing` и `sync` для синхронизации горутин в тестах.
- Для тестирования времени применяйте `time.Sleep` с небольшим запасом (например, TTL = 100ms, ждать 150ms).
- Запускайте тесты с флагом `-race` для проверки отсутствия гонок:
  ```bash
  go test -race -v
  ```

## Дополнительные улучшения

При необходимости функциональность кэша может быть расширена:

1. **Глобальный TTL по умолчанию** – если при `Set` не указан TTL, использовать значение из конфигурации.
2. **Ленивое удаление** (уже реализовано) – дополняет фоновую очистку, снижая нагрузку на ticker.
3. **Статистика** – методы для получения числа записей, количества истекших/очищенных элементов.
4. **Ограничение размера** – интеграция с политикой вытеснения (LRU, FIFO) для предотвращения переполнения памяти.
5. **Параметризация интервала очистки** – возможность изменять интервал во время работы.
6. **Generic-типы** – используя дженерики Go 1.18+, можно сделать кэш типобезопасным: `Cache[K comparable, V any]`.
7. **Настраиваемый таймаут для операций** – например, поддержка `context.WithTimeout` для Get/Set.
8. **Периодическое сохранение на диск** (snapshot) – для восстановления после перезапуска.
9. **Использование `sync.Map`** – для некоторых сценариев может быть более эффективным, но в данной реализации предпочтительнее `RWMutex` для контроля над очисткой.
10. **Пул объектов** – для уменьшения аллокаций при частых операциях.

## Пример использования

```go
package main

import (
    "fmt"
    "time"
)

func main() {
    cache := New(5 * time.Second) // очистка каждые 5 секунд
    defer cache.Stop()

    cache.Set("key1", "value1", 2*time.Second)
    cache.Set("key2", 42, 0) // бессрочная

    val, ok := cache.Get("key1")
    if ok {
        fmt.Println("key1:", val)
    }

    time.Sleep(3 * time.Second)

    val, ok = cache.Get("key1")
    if !ok {
        fmt.Println("key1 истек")
    }

    val, ok = cache.Get("key2")
    if ok {
        fmt.Println("key2:", val) // всё ещё существует
    }
}
```
