# Обработчик больших лог-файлов

## Описание

Данный проект представляет собой консольную утилиту на языке Go, предназначенную для эффективной обработки больших файлов логов (например, размером 100 МБ и более). Программа разбивает входной файл на чанки, обрабатывает их параллельно с использованием горутин, выполняет агрегацию IP-адресов и поиск записей об ошибках, а затем собирает итоговую статистику. Все операции синхронизируются с помощью `sync.WaitGroup`, а доступ к общим данным защищён от состояний гонки.

## Функциональные требования

1. **Чтение файла**  
   - Программа должна принимать путь к файлу логов как аргумент командной строки (или через флаг).  
   - Поддерживаются файлы размером не менее 100 МБ.

2. **Разбиение на чанки**  
   - Файл разбивается на логические части (чанки) для параллельной обработки.  
   - Размер чанка может быть задан пользователем (по умолчанию, например, 1 МБ) или определяться автоматически исходя из количества доступных ядер CPU.  
   - Чанки не должны разрывать строки лога (обработка должна выполняться по строкам).

3. **Параллельная обработка**  
   - Каждый чанк обрабатывается в отдельной горутине.  
   - Количество одновременно работающих горутин ограничено (например, числом CPU или задаётся флагом).  
   - Для каждой строки чанка:
     - Проверяется наличие ключевого слова ошибки (например, `"error"`, `"ERROR"`, `"panic"` и т.п. — список настраиваемый).  
     - Извлекается IP-адрес (предполагается, что он присутствует в стандартизированном формате, например, в поле `remote_addr`).  

4. **Агрегация результатов**  
   - Собирается общая статистика:
     - Общее количество обработанных строк.  
     - Количество строк, содержащих ошибки.  
     - Список уникальных IP-адресов с количеством вхождений (топ-N по желанию).  
   - Результат выводится в консоль или в выходной файл (формат JSON или текстовый).

5. **Синхронизация и безопасность**  
   - Использование `sync.WaitGroup` для ожидания завершения всех горутин.  
   - Использование мьютекса (`sync.Mutex`) или других примитивов синхронизации для защиты общей структуры результатов от конкурентной записи.

6. **Обработка ошибок**  
   - Если файл не найден или недоступен для чтения – программа завершается с понятным сообщением об ошибке.  
   - Если чанк не удаётся обработать (например, из-за повреждённых данных) – ошибка логируется, но не прерывает обработку остальных чанков.

## Технические требования

- **Язык реализации**: Go версии 1.18+ (с поддержкой generics, но не обязательно).
- **Зависимости**: только стандартная библиотека (без внешних пакетов) – допускается использование `encoding/json`, `bufio`, `os`, `sync`, `runtime`, `flag` и т.д.
- **Сборка**: `go build` должен создавать исполняемый файл без ошибок.
- **Платформа**: кроссплатформенность (Windows, Linux, macOS).

## Ограничения

1. **Размер файла** – программа должна корректно обрабатывать файлы объёмом до 10 ГБ (при достаточном количестве оперативной памяти).  
2. **Память** – не допускается загрузка всего файла в память; обработка должна быть построчной, с использованием буферизированного чтения.  
3. **Производительность** – время обработки должно быть пропорционально размеру файла и количеству ядер CPU; ожидается ускорение не менее чем в 2 раза по сравнению с однопоточной обработкой для 100 МБ файла на 4-ядерной машине.  
4. **Формат логов** – предполагается, что каждая строка содержит IP-адрес (в любом месте) и может содержать текст ошибки. Формат строки не жёстко задан, но программа должна быть легко адаптируема под конкретный формат (например, через регулярные выражения).

## Сценарии тестирования

### 1. Тест корректности обработки
- **Вход**: файл с 10 строками, 2 из которых содержат ошибки, IP-адреса: 2 уникальных.  
- **Ожидаемый результат**: общее количество строк = 10, ошибок = 2, IP-статистика = {"192.168.1.1": 5, "10.0.0.1": 5}.

### 2. Тест производительности
- **Вход**: синтетический файл размером 100 МБ со случайными данными.  
- **Ожидание**: время обработки на 4-ядерной машине не превышает 5 секунд (зависит от скорости диска).  
- Сравнение с однопоточной версией для проверки ускорения.

### 3. Тест конкурентной безопасности
- Запуск программы с высоким количеством горутин (например, 100) на большом файле.  
- Использование `go run -race` для проверки отсутствия гонок данных.

### 4. Тест обработки ошибок
- **Вход**: несуществующий файл – программа выдаёт ошибку и завершается с кодом 1.  
- **Вход**: файл с повреждённой строкой (невалидный UTF-8) – программа пропускает строку, логирует предупреждение и продолжает.

### 5. Тест настройки чанков
- Проверка, что чанки не разрывают строки (например, граница чанка попадает в середину строки – программа должна корректно дочитывать до конца строки).  
- Проверка работы с разными размерами чанков (1KB, 1MB, 10MB).

## Рекомендации по реализации

### Архитектура
1. **Парсинг аргументов** – использовать пакет `flag` для задания:
   - `-file` (обязательный) – путь к файлу логов.  
   - `-chunk-size` (опционально, по умолчанию `1MB`) – размер чанка в байтах.  
   - `-workers` (опционально, по умолчанию `runtime.NumCPU()`) – количество параллельных обработчиков.  
   - `-output` (опционально) – файл для сохранения результата (если не указан – вывод в stdout).  
   - `-error-keywords` – список ключевых слов для поиска ошибок (через запятую).

2. **Чтение и разбиение**:
   - Использовать `os.Open` и `bufio.NewReader`.  
   - Для определения границ чанков: читать файл блоками, корректировать конец блока до ближайшего символа `\n`.  
   - Передавать в горутины срез строк (или использовать `bufio.Scanner` внутри каждой горутины, читая из `io.Reader` с заданным смещением).

3. **Параллелизм**:
   - Создать канал задач (`chan []byte` или `chan *Chunk`), куда отправлять чанки.  
   - Запустить пул воркеров (число = `workers`), каждый читает из канала и обрабатывает.  
   - Использовать `sync.WaitGroup` для ожидания завершения воркеров после закрытия канала.

4. **Обработка строки**:
   - Для поиска ошибок: проверить наличие любого из ключевых слов (регистронезависимо, используя `strings.Contains` или регулярное выражение).  
   - Для извлечения IP: использовать регулярное выражение для IPv4 (или IPv6) – например, `\b(\d{1,3}\.){3}\d{1,3}\b`.  
   - Если IP не найден – игнорировать или логировать.

5. **Сбор результатов**:
   - Определить структуру `Result` с полями:
     ```go
     type Result struct {
         TotalLines   int
         ErrorLines   int
         IPCounts     map[string]int
         mu           sync.Mutex
     }
     ```
   - В каждой горутине локально накапливать статистику, а после завершения обработки чанка – заблокировать мьютекс и добавить в общий результат.

6. **Вывод**:
   - Если задан `-output` – записать результат в JSON (или в удобочитаемом виде).  
   - Иначе – вывести в консоль.

### Оптимизации
- Использовать пул байтовых буферов (`sync.Pool`) для снижения нагрузки на GC.  
- Для IP-адресов использовать `map[string]int` – это достаточно эффективно.  
- Рассмотреть возможность сортировки IP-адресов по частоте перед выводом.

## Дополнительные улучшения

1. **Поддержка сжатых файлов** – автоматическое определение GZIP и чтение через `compress/gzip`.  
2. **Регулируемый уровень детализации** – флаг `-verbose` для вывода промежуточной информации (прогресс обработки).  
3. **Фильтрация по времени** – если логи содержат временные метки, добавить возможность фильтрации по диапазону дат.  
4. **Экспорт в CSV или Excel** – для дальнейшего анализа.  
5. **Метрики** – вывод статистики по использованию памяти и времени выполнения.  
6. **Hot-reload** – возможность обработки файла, который активно дописывается (слежение за файлом).  
7. **Конфигурация через файл** – возможность задать параметры (ключевые слова ошибок, формат IP) через YAML/JSON конфиг.  
8. **Тестирование** – написание юнит-тестов для функций обработки строк и интеграционных тестов с использованием временных файлов.  
9. **Graceful shutdown** – обработка сигналов (SIGINT, SIGTERM) для корректного завершения обработки и вывода промежуточных результатов.  
10. **Поддержка IPv6** – расширение регулярного выражения для извлечения как IPv4, так и IPv6 адресов.
